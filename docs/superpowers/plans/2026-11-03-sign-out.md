# Abmelden – sign-out with „Downloads behalten?“ (Plan)

Scope: spec §6a („Beim Abmelden wird gefragt, ob die Downloads behalten werden sollen“), found missing in the tablet
test. Today only `AccountStore.clear(keepDownloads)` exists and nothing calls it. Global constraints of the phase-1 plan
apply (strings in `values/` and `values-de/`, offline first, nothing on a start path awaits the network). 4A/4B/4C
behaviour stays; `CarBrowseTest` must still pass.

## 1. Decisions

| Topic | Decision |
|---|---|
| UI | Settings → new first section „Konto“ (slot like the RMAB/admin sections, own ViewModel): username, server host (public address, else local; port only if not the scheme default), „Admin“ for admins, row „Abmelden“. |
| Before the dialog | Tapping „Abmelden“ pauses playback (so the last position is saved and can be pushed), then pushes what the sync workers would upload – dirty progress rows, unsynced offline sessions, pending (syncable) bookmark changes – with `ProgressSync`/`BookmarkSync` directly, bounded to 15 s, only after the connection check answered online. State „Fortschritt wird übertragen …“ (cancel possible). Afterwards the same three are counted again: that is the warning's N. |
| Dialog | „Abmelden?“, checkbox „Downloads auf diesem Gerät behalten (X)“ default checked, X = bytes on disk under `downloads/<serverId>` (complete files, partial `.part` files, covers); hidden when that is 0 (then nothing is kept). Warning when N > 0 (plurals): kept → „… werden übertragen, sobald du dich wieder mit diesem Konto anmeldest“, not kept → „… gehen beim Abmelden verloren“. „Abmelden“ / „Abbrechen“; while it runs „Abmelden …“ and the dialog cannot be dismissed. |
| Executor | `account/SignOut` (interface `AccountSignOut`, Hilt-bound), small seams so it is unit-testable with fakes. Order: stop playback → cancel the account's work (and wait ≤5 s for running downloads to stop, so no worker writes into deleted dirs) → in parallel the server logout (≤5 s, never blocks) → data (keep: pause queued downloads; else purge) → forget last played server title → clear per-account secrets/caches → `AccountStore.clear(keep)` **last**, so nothing reacts to "signed out" before the data is in its final state. Runs `NonCancellable`. |
| Playback | Stops entirely, also a device title (ruling): `PlayerController.stop()` pauses, waits briefly for the tracker's save, stops and clears the queue; forgets the loaded and the last title (play/pause cannot bring it back). Connects to the service only if it runs. Sleep timer cancelled. `LastPlayedStore` forgets a server title (a device title stays, it is no account data). |
| Work | Cancelled: `sync-periodic`, `sync-now`, `sync-on-online`, `sync-progress`, `sync-bookmarks`, `sync-after-scan`, and every `download-<serverId>-<key>` (from the download rows, plus a new per-server tag on download work). Device folder scans and the cleanup reminder stay. The periodic sync is scheduled again by `syncNow()` (called after every sign-in), KEEP policy. |
| Server logout | ABS 2.37.1 `POST /logout` (no `/api` prefix, no auth needed), refresh token in `x-refresh-token`; answers `{"redirect_url":null}` and invalidates that refresh token (checked against the local test server: refresh afterwards → 401). Unauthenticated, cleartext-guarded client, only to the account's server that is online right now; failure or timeout is ignored. |
| keep = false | `AccountData.purge(serverId)`: one Room transaction deleting every row of `serverId` in every table that has a `serverId` column (list `AccountData.SERVER_TABLES`, checked against the schema by a test), the directory `downloads/<serverId>` (in-flight partial downloads included), the car's cover cache of that server, the sync stamps of that server. `device` and other server ids are never touched; `purge("device")` is refused. |
| keep = true | Files and all rows stay (invisible while signed out; dirty rows sync when the same account returns). Queued/running downloads become PAUSED (their work is gone; the user resumes them). The account is remembered as „kept“ (serverId, username, host) for §5. |
| Secrets and caches | Tokens + account (`AccountStore.clear`), the RMAB connection (token), a pending OIDC attempt, recent searches (the user's own search history), an open download prompt, Coil's memory/disk cache and the car's cover cache (server covers only; covers of kept downloads are files in the download dir and still show offline). Device settings (theme, playback, download settings, tabs) stay. |
| Navigation | `MainViewModel.signedIn` follows the account; when it turns false while the app runs, `AppRoot` shows Setup with a cleared back stack (`NavHostController.showSignIn()`); the next sign-in uses `finishSetup` and lands on the start tab (unchanged). The re-auth Setup on top of the app is not affected (account stays). |
| Previous account | A different account signs in while a kept account exists: once per kept account a dialog „Auf dem Gerät liegen noch Downloads von <user> (<host>, X). Löschen?“ – „Löschen“ purges that serverId (as above), „Behalten“ keeps it and never asks again for it. The same account signing in again removes its kept entry and reuses its data, no dialog. |
| Car, widget, buttons | Already account-scoped: the car tree shows only device titles without an account, `CarStarts`/`LastTitleStarter` refuse titles of another (or no) account, the widget watcher clears a foreign title. Additionally the last-played store forgets the server title and the queue is cleared, so a play key or resumption cannot start the old account's title. |

## 3. Tests

- `AccountDataTest` (Robolectric, in-memory Room): every table with a `serverId` column is in `SERVER_TABLES` (schema via `sqlite_master` + `PRAGMA table_info`) and vice versa; a generic row for A, B and `device` in every such table → purge(A) leaves only B and `device`; files of A gone, B and device covers untouched; counts and sizes; pausing downloads.
- `SignOutTest` (in-memory Room + temp dir + fakes): keep=false deletes only this serverId; keep=true keeps rows/files and only clears credentials; work cancelled for this server; player stopped; logout called with the refresh token, its failure and its timeout ignored; last-played forgets a server title (keeps a device title); kept-account entry written/removed; account cleared last.
- `ServerLogoutTest` + `AuthApiTest` (MockWebServer): route, header, no Authorization header, offline → no call.
- `AccountWorkTest` (work-testing): this server's sync/download work cancelled, another server's download and the device scan/cleanup work untouched.
- `PlayerControllerTest`: `stop()` clears the queue and forgets the title.
- `AccountSectionViewModelTest`: account row, checking → confirm (unsynced N, size, keep default true), checkbox, cancel, confirm → execute(keep) and back to idle; no downloads → keep=false. Compose test of the dialog.
- `PreviousAccountViewModelTest`: shown once for a different serverId with kept data, never for the same account (its entry is removed), „Behalten“ never asks again, „Löschen“ purges.
- `SignOutNavigationTest` (Compose + Robolectric, like `FinishSetupTest`): signed out deep in the app → only Setup is left; the next sign-in lands on the start tab. `MainViewModelTest`: `signedIn` follows the account.
