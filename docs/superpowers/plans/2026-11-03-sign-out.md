# Abmelden – sign-out with „Downloads behalten?“ (Plan)

Scope: spec §6a („Beim Abmelden wird gefragt, ob die Downloads behalten werden sollen“), found missing in the tablet
test. Today only `AccountStore.clear(keepDownloads)` exists and nothing calls it. Global constraints of the phase-1 plan
apply (strings in `values/` and `values-de/`, offline first, nothing on a start path awaits the network). 4A/4B/4C
behaviour stays; `CarBrowseTest` must still pass.

## 1. Decisions

| Topic | Decision |
|---|---|
| UI | Settings → new first section „Konto“ (slot like the RMAB/admin sections, own ViewModel): username, server host (public address, else local; port only if not the scheme default), „Admin“ for admins, row „Abmelden“. |
| Before the dialog | Tapping „Abmelden“ pauses playback (so the last position is saved and can be pushed), then pushes what the sync workers would upload – dirty progress rows, unsynced offline sessions, pending (syncable) bookmark changes – with `ProgressSync`/`BookmarkSync` directly, bounded to 15 s, only after the connection check answered online. State „Fortschritt wird übertragen …“ (cancel possible). Afterwards the same three are counted again: that is the warning's N. |
| Dialog | „Abmelden?“, checkbox „Downloads auf diesem Gerät behalten (X)“ default checked, X = bytes on disk under `downloads/<serverId>` (complete files, partial `.part` files, covers); hidden when that is 0 (then nothing is kept). Warning when N > 0 (plurals): kept → „… werden übertragen, sobald du dich wieder mit diesem Konto anmeldest“, not kept → „… gehen beim Abmelden verloren“. „Abmelden“ / „Abbrechen“; while it runs „Abmelden …“ and the dialog cannot be dismissed. |
| Executor | `account/SignOut` (interface `AccountSignOut`, Hilt-bound), small seams so it is unit-testable with fakes. Order: stop playback → cancel the account's work (and wait ≤5 s until WorkManager applied the cancellation) → in parallel the server logout (≤5 s, never blocks) → data (keep: pause queued downloads; else purge) → forget last played server title → clear per-account secrets/caches → `AccountStore.clear(keep)` **last**, so nothing reacts to "signed out" before the data is in its final state. Runs `NonCancellable`. |
| Playback | Stops entirely, also a device title (ruling): `PlayerController.stop()` pauses, waits briefly for the tracker's save, stops and clears the queue; forgets the loaded and the last title (play/pause cannot bring it back). Connects to the service only if it runs. Sleep timer cancelled. `LastPlayedStore` forgets a server title (a device title stays, it is no account data). |
| Work | Cancelled: `sync-periodic`, `sync-now`, `sync-on-online`, `sync-progress`, `sync-bookmarks`, `sync-after-scan`, and every `download-<serverId>-<key>` (from the download rows, plus a new per-server tag on download work). Device folder scans and the cleanup reminder stay. The periodic sync is scheduled again by `syncNow()` (called after every sign-in), KEEP policy. |
| Server logout | ABS 2.37.1 `POST /logout` (no `/api` prefix, no auth needed), refresh token in `x-refresh-token`; answers `{"redirect_url":null}` and invalidates that refresh token (checked against the local test server: refresh afterwards → 401). Unauthenticated, cleartext-guarded client, only to the account's server that is online right now; failure or timeout is ignored. |
| keep = false | `AccountData.purge(serverId)`: one Room transaction deleting every row of `serverId` in every table that has a `serverId` column (list `AccountData.SERVER_TABLES`, checked against the schema by a test), the directory `downloads/<serverId>` (in-flight partial downloads included), the car's cover cache of that server, the sync stamps of that server. `device` and other server ids are never touched; `purge("device")` is refused. |
| keep = true | Files and all rows stay (invisible while signed out; dirty rows sync when the same account returns). Queued/running downloads become PAUSED (their work is gone; the user resumes them). The account is remembered as „kept“ (serverId, username, host) for §5. |
| Secrets and caches | Tokens + account (`AccountStore.clear`), the RMAB connection (token), a pending OIDC attempt, recent searches (the user's own search history), an open download prompt, Coil's memory/disk cache and the car's cover cache (server covers only; covers of kept downloads are files in the download dir and still show offline). Device settings (theme, playback, download settings, tabs) stay. |
| Navigation | `MainViewModel.signedIn` follows the account; when it turns false while the app runs, `AppRoot` shows Setup with a cleared back stack (`NavHostController.showSignIn()`); the next sign-in uses `finishSetup` and lands on the start tab (unchanged). The re-auth Setup on top of the app is not affected (account stays). |
| Previous account | A different account signs in while a kept account exists: once per kept account a dialog „Auf dem Gerät liegen noch Downloads von <user> (<host>, X). Löschen?“ – „Löschen“ purges that serverId (as above), „Behalten“ keeps it and never asks again for it. The same account signing in again removes its kept entry and reuses its data, no dialog. |
| Car, widget, buttons | Already account-scoped: the car tree shows only device titles without an account, `CarStarts`/`LastTitleStarter` refuse titles of another (or no) account, the widget watcher clears a foreign title. Additionally the last-played store forgets the server title and the queue is cleared, so a play key or resumption cannot start the old account's title. |

## Implementation notes (2026-11-03)

- **What counts as "unsynced"** (`AccountData.unsynced`): dirty progress rows, unsynced `local_sessions` and bookmarks
  with a pending UPSERT/DELETE, each with the filters the syncs use – device keys never count, episode bookmarks never
  count (they never leave the device by design, so they are not "not yet on the server"; with keep=false they are
  deleted without a warning).
- **Download size** = bytes on disk under `downloads/<serverId>` (complete files, `.part` files, covers), not the DB
  sums: that is what the checkbox keeps or deletes. A partially downloaded stream (download on play) counts.
- **Tables** (`AccountDataDao.SERVER_TABLES`, 15): libraries, items, chapters, audio_files, progress, local_sessions,
  downloads, episodes, external_series, title_audio, bookmarks, queue, history_sessions, collections,
  collection_entries. `local_folders` and `local_titles` have no `serverId` (device library) and stay. The queue of an
  account may hold device keys (`local:`); they go with the account's queue (the queue is account data), the device
  titles themselves stay.
- **Outside Room**: sync stamps `progress_sync:<id>` / `collections:<id>` (purge only; otherwise the collections would
  not be fetched again after a re-sign-in), the car cover cache `cache/car_covers/<id>` and Coil's memory/disk cache
  (always), last played (server title only), RMAB token, pending OIDC attempt, recent searches, an open download prompt
  (always). Kept as device settings: playback/download/ui settings, tab layout, `cleanup_ignored` and
  `auto_downloaded_episodes` in `app_settings` (keyed `serverId:…`, harmless, tiny), the in-memory `AuthorInfoCache`
  (keyed by server id, process lifetime).
- **Playback**: the dialog's check pauses playback (so the last position is saved and pushed before the dialog); the
  sign-out stops and clears the queue. A paused player is stopped without waiting; a playing one gets 300 ms for the
  tracker's save first.
- **Server logout** runs alongside the data step and is only awaited before the credentials go (≤5 s); offline it is
  skipped, a failure (e.g. `ConnectException`) only logged.
- **Work**: `getWorkInfos…` reports CANCELLED as soon as WorkManager recorded the cancel, so the wait only makes sure
  the (asynchronous) cancel operations are applied. A download in the middle of a chunk stops at its next
  `ensureActive`; its writes after that are conditional updates that match nothing once the rows are gone.
- **Found on the emulator**: the previous-account watcher filtered `null` before `distinctUntilChanged`, so the same
  account signing out and in again in one process kept its "kept" entry (fixed, test added). The size in the checkbox
  broke between number and unit (non-breaking space now).
- **Emulator check** (emulator-5554, ABS 2.37.1 test server; a second server id simulated with `adb reverse` →
  `http://127.0.0.1:13378`, same ABS user, so no extra account on the server): keep=true → rows and files stay, sign-in
  again → downloads offline at once, no question; another server id → question once, „Behalten“ → never again,
  „Löschen“ → exactly that server id's rows, files and stamps gone; keep=false while playing → playback stopped, every
  row and file of the server gone, device titles (2) and their rows untouched; offline (reverse removed) → the push
  fails fast, the dialog warns „2 changes …“ (kept / lost variant), logout fails and is ignored. A play key after the
  sign-out starts nothing. Emulator left signed in with the three downloads restored.

## Fix round 1 (review, 2026-11-03)

Rulings of the review (`signout-review-fixes.md`), all implemented:

- **I1 failed purge**: `AccountData` is an interface now (`DeviceAccountData`); `purge` throws when files are left
  (`deleteRecursively()` checked). SignOut records a pending purge (`KeptAccountStore.pendingPurges`) when it fails;
  `AccountDataJanitor` (every app start) retries it – dropped when that account signed in again – and deletes
  `downloads/<id>` directories nobody owns (no rows in any of the 15 tables, not the signed-in account, not kept, not
  pending; the device library has no download directory). „Löschen“ in the previous-account dialog goes through
  `KeptAccountDeletion`: purge, forget the entry only on success, otherwise put it back (not asked) and show „Es ließ
  sich nicht alles löschen …“; never throws.
- **I2 tests**: `SignOutTest` records every step and asserts the whole order (stop → work → purge/forget or
  pauseDownloads/remember → last played → account state → rows again → clear; the logout between work and the rows);
  a cancelled caller still ends signed out (fails without `NonCancellable`); keep=true leaves stamps and car covers.
  `AccountStateCleaner` (RMAB, OIDC, recent searches, prompts, image caches, cleanup notification) is its own class,
  tested with the real stores. `ServerLogout` never follows a 307; `AccountWorkTest` stops a RUNNING worker.
- **M1**: `updateTokens` / `markNeedsReauth` write only while an account is stored (same edit).
- **M2**: without keeping, the rows are deleted once more right before the credentials go (after the logout await).
  `queueOwner`: the service's queue advance continues only the signed-in account's queue (device titles only while
  signed in) and re-checks the owner before each start, leaving the queue untouched otherwise.
- **M3**: `execute(keep=false, shownUnsynced)` counts again after playback stopped; more than shown →
  `SignOutResult.Changed`, nothing touched, the dialog asks again with the new count and the same choice.
- **M4**: the checkbox also shows with unsynced changes and no downloads: „Daten auf diesem Gerät behalten“ (checked).
- **M5**: signed out, the car's root holds only „In Lauschig auf dem Handy anmelden“ (not playable, not browsable);
  every folder is empty, search and voice find nothing, starts and resumption fail with that text; `LastTitleStarter`
  resumes nothing while signed out. `CarSignedOutTest` (instrumented) runs while the device is signed out, skipped
  otherwise.
- **M6**: the cleanup reminder is cancelled on sign-out; signed out, `OPEN_CLEANUP`, the widget's player request and
  links are dropped (`incomingGate`), the SSO callback is not gated.
- **M7 (part)**: `KeptAccount.userId`; the Downloads page lists „Downloads früherer Konten“ with size (or „Daten, keine
  Downloads“) and a delete action behind a confirmation, also after „Behalten“. The one-time question stays.
  **Known gap (out of scope):** the re-auth Setup is pre-filled but editable; signing in there with another account or
  other addresses changes the server id without going through SignOut (no work cancelled, no kept entry). Later: route
  a re-auth to a different server id through SignOut(keep=true).
- **M8**: purge order stamps → rows → files. **M9**: a failing check asks anyway with „Ob noch Änderungen fehlen, ließ
  sich nicht prüfen.“ (keep checked). **M10**: the schema guard flags any column containing "server" that is not the
  handled `serverId` (`bookmarks.onServer` listed as a flag).
